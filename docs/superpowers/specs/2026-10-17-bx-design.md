# bx — Agent-Agnostic Browser Control: Design Spec

Date: 2026-10-17
Status: Draft for review
Product name: **Kitestring** (decided 2026-10-18; was working name `bx`). CLI binary `kite`, npm scope `@kitestring/*`, native host `com.kitestring.bridge`, home `~/.kitestring` (`KITE_HOME`), session env `KITE_SESSION`. Metaphor: the agent flies the browser, the human holds the string.

## 1. Problem

Coding and general agents (Claude Code, Codex, Cursor, Gemini CLI, OpenCode) need to use a browser. Existing tools either launch a fresh browser with no logins, work for a single agent only, burn tokens on huge DOM dumps and screenshots, or take many slow LLM round trips to find and click one element.

## 2. Product

A Chrome extension plus a local bridge that lets **any** agent control the user's **real, logged-in Chrome** through one of three front doors: MCP server, `bx` CLI, or local JSON-RPC socket. Ships with Agent Skills (`SKILL.md`) and a one-command installer that wires every detected agent.

## 3. Architecture

```
Agents ──MCP stdio──┐
Agents ──bx CLI─────┼──JSON-RPC over Unix socket (~/.bx/bx.sock, mode 0600)──► Host daemon
                    ┘                                                         │
                                                Chrome Native Messaging (stdio)│
                                                                              ▼
                  Plasmo MV3 extension: background service worker (sessions, CDP, guards, pipeline)
                                        content script "page agent" (snapshot, find, check, quiet)
                                        side panel (live feed, approvals, handoff)
```

- **Host daemon** is the native messaging host. Chrome spawns it when the extension calls `chrome.runtime.connectNative`. It lives as long as that port. It serves the socket for CLI and MCP clients.
- **No TCP port** is opened. Web pages cannot reach the bridge.
- **Background** owns tabs, tab groups, `chrome.debugger` (CDP 1.3) sessions, network-idle tracking, and the action pipeline.
- **Page agent** is a pure-TS library (`packages/page-agent`) bundled into a Plasmo content script. It reads the DOM; it never dispatches input. Input is dispatched by CDP so events are trusted.

## 4. Core concepts

- **Session**: a named agent context (`BX_SESSION` env or `--session`, default `default`). Each session owns one Chrome tab group (title = session name) and an "active tab". Sessions cannot touch tabs they do not own.
- **Target**: how an action names an element. `"@e3f2a"` = ref; any other string = visible text or label. Optional `within` (landmark/heading/region name) and `role` narrow it. Resolved lazily at execution time.
- **Ref**: stable id `@e` + 5 base36 chars, hash of role + accessible name + landmark path + occurrence index. Survives re-renders that keep the same content.
- **Snapshot**: compact text of interactive elements and landmarks, viewport-scoped by default:
  ```
  page "Checkout" https://shop.test/checkout
  main
    heading "Shipping address"
    textbox "Full name" [@e1k2d9] value=""
    combobox "Country" [@e0p3la] value="India"
    button "Continue" [@e7hs02] disabled
  list "Results" (50 items) item[0..2] … +47
  ```
- **ActionResult**: every action returns status + diff + page brief in one response, so the agent needs no follow-up snapshot.

## 5. Action pipeline

`FIND → CHECK → ACT → WAIT → VERIFY → REPORT`

| Stage | Rule |
|---|---|
| FIND | Rank candidates: exact accessible name 100, exact label/placeholder 95/90, starts-with 70, contains 50, token-overlap ≥ 0.6 → 30. +5 visible, +3 in viewport. Text normalized (NFKC, nbsp→space, collapse whitespace, case-fold). Top two within 5 points and both ≥ 50 → `ambiguous` with top 3 candidates. Not found → scroll down one viewport and retry, max 3 times. |
| CHECK | Scroll into view (center). `elementFromPoint` at center must be the element or its descendant, else `blocked` with description of the covering element. Disabled → `disabled` with visible form errors. |
| ACT | CDP `Input.dispatchMouseEvent` (click), `Input.insertText` after select-all (fill), `Input.dispatchKeyEvent` (press), DOM value set + `input`/`change` events (native `<select>`), CDP `mouseWheel` (scroll). |
| WAIT | Ready = DOM quiet 300 ms (ignoring `style` attribute churn) AND no visible `[aria-busy=true]`/`[role=progressbar]` AND network quiet 300 ms (ignoring WebSocket, EventSource, Ping, and analytics hosts). Max 10 s → `timeout` status but still report. |
| VERIFY | Diff before/after snapshot. Click with empty diff, same URL, no new tab → `no_effect`. Fill reads value back; mismatch → `error`. |
| REPORT | `{ok, status, diff{added,removed}, navigation?, newTabs?, errors?, candidates?, blockedBy?, page}` |

## 6. Batching

`batch` runs a list of steps with lazy targets. Step options: `wait` (ms to wait for target to appear), `expect` (`{text}` or `{url}`), `if_present` (skip silently if target missing). Halts and returns state on: not found, ambiguous, blocked, domain change, unexpected dialog, failed `expect`, or a step at risk level red. Batch result = per-step results + final page state.

## 7. Guards (always on, background)

Alert guard (CDP `Page.javascriptDialogOpening` → auto-dismiss/accept per policy, logged), popup closer (cookie/newsletter pattern list), tab watcher (`openerTabId` → adopt new tabs/popups into session), domain guard (halt on unexpected domain), login/captcha detector (→ handoff), keep-alive and auto-reconnect, step checkpoints in `chrome.storage.session`, tab ownership lock, focus emulation for background tabs.

## 8. Risk levels

| Level | Examples | Rule |
|---|---|---|
| green | scroll, open menu, read, search | auto-retry allowed |
| yellow | save, submit, add to cart | never auto-retry; verify first |
| red | pay, buy, send, delete, publish, place order | human confirms in side panel every time |
| secret | password, card number, OTP fields | agent may not type; handoff |

Classifier: button/link text keywords, input `type`/`autocomplete` (`password`, `cc-*`, `one-time-code`), user deny-list domains. Unsure → red.

Page text returned to agents is wrapped in `<page_content>` tags. Hidden text (zero-size, off-screen, same color as background) that reads like an instruction is flagged in the report.

## 9. Agent integration

- `bx mcp`: MCP stdio server exposing the same operations as the CLI.
- `bx init`: detects Claude Code, Codex, Cursor, Gemini CLI, OpenCode; registers MCP; copies skills; installs the native host manifest; opens extension install page; runs `bx doctor`.
- Skills pack: `browser` (core loop + speed rules + batching rules), `browser-debug-frontend`, `browser-e2e-verify`, `browser-extract`, `browser-forms`, `sites/*` recipes.

## 10. Speed & growth features

Action cache (domain + path pattern + intent → selector chain, self-healing), learned site memory, `bx do "<intent>"` executed by a small fast model, record → skill, time-to-done benchmark, torture-test site published as a standalone benchmark.

## 11. Non-goals (v1)

Windows support (registry-based host install) until M6. Firefox/Safari. Remote/cloud browsers. Bypassing captchas or bot detection. Cross-origin iframe input until M4.

## 12. Constraints

- Node ≥ 22 LTS for the host/CLI. Package manager: pnpm workspaces.
- Plasmo (latest 0.x) for the extension, React for the side panel.
- Chrome MV3 permissions: `debugger`, `tabs`, `tabGroups`, `scripting`, `nativeMessaging`, `storage`, `sidePanel`; host permissions `<all_urls>`.
- Native host name: `com.bx.bridge`. Socket: `$BX_HOME/bx.sock` (default `~/.bx`), mode 0600. Host logs to `$BX_HOME/logs/host.log`; host stdout carries only framed messages.
- Native messaging limits: host → Chrome messages ≤ 1 MB; Chrome → host ≤ 64 MB.
- Fixed extension ID via manifest `key`, so `allowed_origins` in the host manifest is stable.

## 12a. Testing

- Unit: Vitest (protocol, host, CLI).
- Page agent: Playwright Test against fixture HTML with the agent bundle injected (real layout engine).
- End to end: Playwright launches Chromium with the built extension and the host manifest in the temp user-data-dir, runs the real `bx` CLI against the **torture site** (`apps/torture`), and asserts `window.__result` on each page.
